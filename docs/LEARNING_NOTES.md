## 〇、总纲：一句话主线

> **蒙眼走 1m = IMU（预测）；睁眼看到 0.8m = 雷达（观测）；K 是投piao法官，P 是信心计。**

- 预测（IMU）：快、高频、但会漂（误差累积）
- 观测（雷达/激光/里程计）：慢、低频、绝对（不背历史错误）
- ESKF 的活：让快的撑住高频，让慢的定期校准，用 K 按各自"没谱程度"投票

## 一、概念区："这俩到底啥关系？"

### Q1：IMU 到底测什么？
- **陀螺仪**：角速度 ω（rad/s），瞬间的转动快慢
- **加速度计**：**比力 f**，不是"运动加速度"！f = 加速度 − 重力
  - 静止放桌上读 **9.8**（在对抗重力）
  - 自由落体读 **0**（失重，加速度计和你一起掉）
- IMU 是**本体感觉**，只测"瞬间量"，没有绝对参考 → 要位置只能**积分** → 积分 = 误差累积 = 会漂

### Q2：里程计 / 雷达扮演什么角色？
- 轮式里程计、视觉、激光都是**外部观测**，给的是"位移/位置"这种**绝对信息**
- 误差**不会**像 IMU 二次积分那样指数膨胀
- 在 ESKF 里：IMU 负责高频预测，观测负责低频校准

### Q3：K 越小/越大，信谁？
> **K 越小 → 信 IMU（预测）；K 越大 → 信雷达/里程计（观测）。**
- K≈0：预测超准/观测超吵 → 信预测
- K≈1：观测超准/预测超没谱 → 信观测
- 起步没谱时 K≈0.99（几乎全信观测），稳态 K≈0.10（几乎全信 IMU）

### Q4：P 是啥？
- P = "我对自己状态估计有多没谱"（方差）
- 呼吸节奏：**预测让它涨（+Q），观测让它缩（×1-K）**
- 稳态 P 有多大，估计误差的标准差就有多大（√P）

### Q5：Q 和 R 的区别？（曾记反）
- **Q 对模型**：我对"模型猜得准不准"的信心（世界在动、模型粗糙 → Q 大）
- **R 对传感器**：传感器有多吵（物理常数，改 Q 不影响 R）
- 改 Q → P 涨得狠 → K 变大（更信观测，因为模型不靠谱）

### Q6：模型失配（重点预警）
- 场景：模型说"它不动"，实际车在 20m/s 往前开 + 我们不信观测（K 小）
- 结果：估计**追着真值跑但永远差一截**，形成稳定"滞后误差"
- 这是系统偏差（不是噪声），ESKF 要对抗的核心难题之一

### Q7：exp(δθ) 到底是啥？（通俗版）
- **δθ 是"指令"**：人话，如"往右歪 2°"，是个 3 维向量
- **exp 是"翻译官"**：把指令翻译成四元数（绕某轴转几度的机器语言）
- **q ⊗ exp(δθ) 是"执行"**：把这次小旋转叠到当前姿态上
- 为什么要翻译？四元数乘法才能"叠旋转"，向量不能直接加

## 二、数学区："为啥不能这样"

### 姿态为什么不能当向量？
- 旋转**不满足交换律**：先转 z 90° 再转 x 90°，和反过来，结果不同
- 实测：两个 90° 交换顺序差 **0.174**；两个 2° 差 **0.0247**（量级，不是 100 倍）
- 位置可以加（2m+3m=5m），姿态不能加（转 90° + 转 90° ≠ 转 180°）

### 小误差为什么能当向量？
- 因为**小角度几乎可交换**（2° 差 0.0247，真实 ESKF 误差 0.001° 量级，差小到忽略）
- ESKF 的灵魂：**不滤波姿态本身，滤波"姿态的误差"**（Error State 名字的由来）
- 算完用指数映射叠回大姿态：`大姿态 ⊗ exp(δθ)`

### 右乘先发生（容易记反）
- `q_big * exp(δθ)` = **先 exp(δθ) 小误差**，后 q_big 大姿态
- `exp(δθ) * q_big` = 先 q_big，后 exp(δθ)
- ESKF 更新姿态的标准写法：`exp(δθ) * q_big`

### 四元数几何
- `(x,y,z,w) = (轴 × sin(θ/2), cos(θ/2))`
- 单位四元数 `(0,0,0,1)` = 不旋转；`|q|≡1` 是它不会变形的保障

## 三、代码区："卧槽，这也能错"

| 坑 | 真相 | 怎么记 |
|---|---|---|
| `M_PI` 未声明 | **MSVC（Windows）没有，GCC/Clang（Linux/Mac）有** | 用 `#ifndef M_PI #define M_PI 3.14...` 包一层 |
| `Quaterniond` 参数顺序 | 是 `(w, x, y, z)`，**w 在第一位** | 别写 `(x,y,z,w)`，会转反 |
| Eigen `.z()` 带括号 | `v.z()` 是函数调用，`v.z` 是成员指针，报错 | 向量分量都用 `.x()/.y()/.z()` |
| main 只能有一个 | 两个 `.cpp` 各写 main → LNK2005 重复定义 | 每个程序一个 main，一个程序一个文件 |
| `/O2` 与 `/RTC1` 冲突 | Debug 默认 `/RTC1`，`/O2` 优化和它打架 | 优化级别和运行期检查别同时开 |
| cmake 不在 PATH | 要用完整路径 | `"C:/Program Files (x86)/.../CMake/bin/cmake.exe"` |
| cl 找不到标准库 | cl 需要 vcvars64.bat 环境 | 要么用 `build.cmd`，要么先 `call vcvars64.bat` |

## 四、ESKF 阶段（阶段4 追加）

### 面试级一句话总结（打磨版，背下来）
> "位置/速度用标准卡尔曼：IMU 高频预测，观测低频校正，K 按可信度加权。姿态因为是四元数不能直接加减，就单独走误差状态 —— 滤波的是姿态的误差 δθ，算完用指数映射叠回大姿态。这样既躲开了姿态不可交换的问题，又能把偏置这种'看不见的状态'通过相关性学出来。"
- 结构：预测+观测+加权（位置）+ 误差状态+叠回（姿态）
- 被追问的两点：①为什么姿态走误差状态 → 旋转不可交换 ②ESKF 值钱在哪 → 偏置也能被相关性学出来

### 15 个观测 vs 15 个状态（最反直觉的一环）
- ESKF 误差状态 15 维（δp δv δθ δb_g δb_a），观测只有 3 维位置
- **凭什么 3 个能修正 15 个？靠 P 的交叉协方差（非对角块）**
- 因果链：陀螺偏置 → 姿态偏 → 速度偏 → 位置偏。所以"位置误差"和"偏置误差"在历史上相关，记在 P 里
- 观测发现位置偏 → 通过相关性"牵连"修正偏置/姿态/速度
- 比喻：只看得到温度计（位置），但靠"炉子烧久房间热"（相关性）推断炉子功率（偏置）
- 记忆点：`P·Hᵀ` 把"看得见的观测"映射到"看不见的状态"

### 偏置是"被学出来的"，不是猜的
- ESKF 不知道真偏置，但从数据里收敛到真值附近（b_g≈[0.02,-0.02,0.02] vs 真值 [0.02,-0.03,0.05]）
- 这就是能治偏航漂移的根本：把"为什么漂"的根源直接抓出来，积分前减掉
- 阶段1 漂 29° 的元凶 = 陀螺 z 偏置 0.05，阶段4 把它估出来了

### 观测频率直接决定误差上限
- 5Hz 观测（obs_every=20）→ ESKF 误差稳在 0.3m，纯积分漂到 31m，改善 47 倍
- 观测变稀 → 修正次数变少 → 两次观测间 IMU 漂更久 → 误差变大
- 规律：观测频率是 ESKF 性能的"天花板"

### 阶段4 实测结果（可做简历素材）
| k | 纯积分误差 | ESKF 误差 | 改善 |
|---|---|---|---|
| 2.5s | 1.45m | 0.42m | 3.4× |
| 5s | 7.35m | 0.38m | 19× |
| 7.5s | 18.03m | 0.33m | 55× |
| 10s | 31.45m | 0.38m | 84× |

- 全程位置 RMSE：纯积分 14.15m vs ESKF 0.30m，压到 47 分之一
- 时间越长，ESKF 优势越大（误差差距 3.4× → 84×）

### 一维 → ESKF 对照表（理解升级的关键）
| 一维（阶段2） | ESKF（阶段4） |
|---|---|
| `P += Q` | `P ← F·P·Fᵀ + Q` |
| `K = P/(P+R)` | `K ← P·Hᵀ·(H·P·Hᵀ+R)⁻¹` |
| `x̂ += K(z-x̂)` | `δx ← K·(z-h(x̂))`，再叠回大状态 |
| `P *= (1-K)` | `P ← (I-K·H)·P` |
| 状态 1 个数 | 状态 15 个（δp δv δθ δb_g δb_a） |

## 五、评估阶段（阶段5 追加）

### ATE vs RPE（面试会问）
- **ATE** = 绝对轨迹误差：每时刻估计-真值距离的 RMSE。管"整条线离多远"，**最敏感累计漂移**（越飘越远单调暴涨）
- **RPE** = 相对位姿误差：固定间隔 Δ 内"位置增量"的偏差。管"每段步子稳不稳"，**看不出趋势**（恒定局部偏差时 RPE 稳定不涨）
- 例子：平行偏移 1m → ATE 大、RPE 小（ATE 盲区）
- 两者互补，一起算才完整

### 阶段5 实测（简历素材）
- `src/stage5_eval.cpp` 输出 ATE/RPE + 导出三条轨迹到 data/traj.csv
- `scripts/stage5_plot.py` 画轨迹对比 + 误差曲线（matplotlib，中文字体 SimHei）
- 结果：ATE 纯积分 14.14m → ESKF 0.30m（47倍）；RPE 3.69m → 0.44m（8倍）
- 纯积分最大误差 29.77m，ESKF 最大 0.74m，ESKF y 范围 -5.17~5.27（真值圆半径5）
- 图片在 data/traj_compare.png、data/err_over_time.png

### 中文字体坑（matplotlib）
- matplotlib 默认 DejaVu Sans **没有中文字形**，中文标签全变方块
- 修法：`font_manager.fontManager.addfont("C:/Windows/Fonts/simhei.ttf")` + `rcParams["font.sans-serif"]=["SimHei",...]` + `axes.unicode_minus=False`
- 注意：RGBA 的 png 某些工具读不了，可转 RGB

## 六、阶段6（EuRoC 真实数据管道，仿真先行验证）

### 阶段6 和阶段4 的差别（都是"真实数据"逼出来的）
- 阶段4 读的是无时间戳的二进制流 + 解析真值；阶段6 读 EuRoC CSV（纳秒时间戳）
- 每步 dt 用真实时间戳差值（真实 IMU **不是**严格均匀采样）→ `predict()` 接收每步实际 dt
- 观测调度按**时间戳**驱动（GT 每 0.2s 给一个位置观测），绝不按"第几个索引"对齐 —— 两个传感器各有各的时钟
- 噪声参数从 `sensor.yaml` 读"噪声密度"（σ := density）
- 姿态/重力符号自检：静态 acc z 应 ≈ +9.81（若 ≈ -9.81 说明重力符号反了）

### 诚实声明：EuRoC 没有位置传感器
EuRoC 只有 IMU + 相机。代码里用"真值位置 + 小噪声(σ=0.1)"充当位置观测替身（和阶段4 用解析真值当雷达同构）。所以"两次观测之间 IMU 的传播质量"依然是有意义的评价。

### 真实数据下载是大坑 → 先仿真跑通全链路
官方 zip（vicon_room1 ≈ 6GB）绝大部分是相机图片，且**zip 里套着 zip**（V1_01_easy.zip 是 deflate 压缩，无法用 HTTP Range 钻取内层文件）。remotezip 只能拉 5MB 的小文件，但前提是外层 zip 直接含 CSV —— 实际不是。
降级方案：先用 `scripts/gen_euroc_sim.py` 生成 **EuRoC 同款目录结构**的仿真数据（`imu0/data.csv` + `sensor.yaml` + `state_groundtruth_estimate0/data.csv`），`stage6_euroc` 零改动直接读。数据到位后换目录跑即可。

### 阶段6 实测（仿真 15s 圆周，5Hz 位置观测，简历素材）
| 指标 | 纯积分 | ESKF | 改善 |
|---|---|---|---|
| ATE | 30.20 m | 0.133 m | 227× |
| RPE | 5.27 m | 0.173 m | 30× |
| 最大误差 | 68.68 m | 0.334 m | — |
- 偏置估计：b_g ≈ [0.018, -0.028, 0.048] vs 真值 [0.02, -0.03, 0.05]（几乎全对）
- b_a ≈ [0.062, -0.198, 0.098] vs 真值 [0.10, -0.20, 0.10]（y/z 全对，x 差一半 —— 圆周平面运动里 b_a.x 与水平运动耦合，可观测性弱；偏航 b_g.z 弱可观测是老规矩）
- 图：data/euroc_traj_compare.png、euroc_err_over_time.png、euroc_bias.png

### 踩坑记录（全是血泪）
1. **噪声密度换算（最狠的一个）**：仿真注入的是"每样本"标准差 σ_s，而 stage6 把 sensor.yaml 的 density 当连续 PSD 密度用 `Q = density²·dt`。正确换算是 **density = σ_s·√dt**（乘 √dt！）。我写成 ÷√dt，Q 被放大 40000 倍 → 偏置完全学不出来、误差反而大。
   - **ROS2 节点也一样**：`imu_sim.bin` 是 100Hz（每样本 gyro σ=0.01），但节点默认 `sigma_g=1.7e-4`（200Hz EuRoC 密度），没传参直接跑 → 7s 就漂 6m。换算成 `sigma_g=0.01·√0.01=0.001` 后 ATE 回到 0.33m。**换数据/换频率，先对噪声参数**。
   - 验证方法：一步积分的速度/角度不确定度增量 = σ_s²·dt²，令 Q = density²·dt = σ_s²·dt² → density = σ_s·√dt
   - 记法：**"乘根号dt"** —— Q 里已经有个 dt 了，density 必须补 √dt 才能凑出 dt²
2. **"最大误差"别写成离原点的距离**：`e.squaredNorm()` 是模长平方（离原点），不是和真值的误差。要 `(est - tru).norm()`。写错会打出 5.16m 这种假 spike（其实是轨迹半径 5m）。
3. **导出 CSV 时偏置历史别填 0**：主循环里记了 bg_hist/ba_hist，导出时要 `sample_at_gt` 重采样到 GT 时间轴，否则画图没有偏置收敛曲线。
4. **Linux 中文字体**：Noto 的 .ttc 注册后 matplotlib 里字族名是 **"Noto Sans CJK JP"**（不是 SC），fallback 列表要带上；备选 Droid Sans Fallback。
5. **RGBA 的 png 某些工具读不了**：转 RGB（`im.convert('RGB')`）。

### 6b：ROS2 节点端到端（把 ESKF 落地成节点）
- 完整链路：`ros2 bag play`（数据源）→ `/imu`+`/odom` 话题 → `eskf_node` 节点 → `/odom_filtered` → `ros2 bag record` → `eval_ros.py` 算 ATE/RPE
- 节点复用 `include/eskf.hpp`（和独立版 stage6 同一份核心），用首条 `/odom` 的位置+朝向+速度初始化，之后只当位置观测
- 一键运行：`ros2 launch eskf_ros eskf_ros.launch.py` → 清bag→节点→record→play→自动优雅退出
- **实测（ROS2 链路）**：ATE 0.33m / RPE 0.46m，与独立版一致（简历素材）
- 节点和 launch 都迁入仓库 `ros2_ws/src/eskf_ros/`，include 路径改相对，统一管理
